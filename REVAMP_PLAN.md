## 0. Краткая сводка жалоб владельца → корневые причины

| Жалоба | Корневая причина | Где |
|--------|------------------|-----|
| «Общается как робот» | `temperature=0.35` + penalties + агрессивная постобработка режет пунктуацию + repeat guard подменяет живые реплики канцеляритом | config.py, postprocessing.py |
| «Хуёво запоминает людей» | Профиль затирается пустотой каждый ход; keyword-гейт не пускает факты на извлечение; рассогласование порогов importance | memory_engine.py, db.py |
| «Багованная, пердит» | Общее aiosqlite-соединение + fire-and-forget commit поверх BEGIN; `/sleep` рубит соединение под задачами; лишние последовательные LLM-вызовы | db.py, agent.py, main.py, generation_pipeline.py |
| «Громоздкая, всё в 1 файл» | Модули распухли (main 1453, db 1376, context_builder 1131, memory 1103) | вся кодовая база |

## 1. ХАРАКТЕР / ЖИВОСТЬ (приоритет: высокий, риск: низкий)

### Диагноз
Бот звучит как ассистент, потому что вся система настроена на детерминизм и «безопасный средний вариант», а постобработка добивает живую речь.

**1.1. Зажатый сэмплинг** — `config.py:165-168`
- `TEMPERATURE = 0.35` — уровень детерминированного ассистента. Для персонажа ~20 лет нужно 0.7–0.85.
- `TOP_P = 0.85` — дополнительно режет хвост распределения.
- `FREQUENCY_PENALTY = 0.15`, `PRESENCE_PENALTY = 0.1` — на коротких русских репликах штрафуют естественный повтор служебных слов, ломают речь.

**1.2. Постобработка калечит текст** — `postprocessing.py`
- `:326-327` — удаляет финальную точку и `,;:` («признак ИИ») → ответы рубленые, обрывистые.
- `:308` — заменяет тире `—`/`–` на ` - ` → насилие над русской типографикой.
- `:323` `_shrink_reply_text` — жёстко режет до 8 предложений / 700 символов.
- `_fix_gender` (`:261`) — десятки хрупких regex; «я был рад» чинит только первое слово, может коверкать чужую речь в цитате.

**1.3. Repeat guard душит короткие реплики** — `postprocessing.py:344-355`, `agent.py:227-249`
- `_looks_like_same_reply_key` считает повтором подстроку ≤28 символов. «ага», «норм», «лол», «ну да» естественно повторяются → каждый раз триггерят перегенерацию.
- На 3-м шаге подменяет реплику на казёнщину: *«Давай по делу: что именно нужно?»* (`:402-408`).
- Окно `REPEAT_GUARD_WINDOW = 6` — в активном чате ловит много ложных срабатываний.

**1.4. Лишний `edit_answer` на коротких репликах** — `agent.py:209-213`, `generation_pipeline.py:769-772`
- Срабатывает при `short_draft` (<15 символов), temp зажата до 0.2–0.45.
- Делает второй LLM-вызов именно на самых живых коротких ответах → задержка + обезличивание.

**1.5. Переусложнённый системный промпт** — `generation_pipeline.py:476-514`, `prompts.py`
- Гендерное правило повторяется трижды (база, хвост `:503`, fix-регексы). Много противоречивых «будь живой / соблюдай формат / не делай / не объясняй» инструкций давят слабую локальную модель.

### План правок — характер
- [ ] **1.1** `config.py`: `TEMPERATURE` 0.35→0.8, `TOP_P` 0.85→0.92, `FREQUENCY_PENALTY` 0.15→0.0–0.05, `PRESENCE_PENALTY` 0.1→0.0. (Проверить, что значения берутся из .env — поправить и .env.example.)

- [ ] **1.2c** Поднять/смягчить `MAX_EDITOR_SENTENCES`/`MAX_EDITOR_REPLY_CHARS` — но аккуратно, длина в чате должна быть короткой. Решить: оставить лимит, но не дробить речь.

## 2. ПАМЯТЬ (приоритет: критичный — потеря данных, риск: средний)

### Диагноз

**2.1. ЗАТИРАНИЕ ПРОФИЛЯ ПУСТОТОЙ — потеря данных каждый ход** ⚠️
`memory_engine.py:848-858` + `db.py:839`
- `interests = _join_list(profile.get("interests"))` → если LLM в этом ходу вернул пустой массив (а промпт велит возвращать пусто, если интересов в сообщении нет), то `interests=""`.
- `upsert_user_profile(..., interests="")` → в `db.py:839` логика `interests if interests is not None else current`: пустая строка `""` ≠ `None` → **перезаписывает накопленные интересы пустотой**.
- `communication_style`/`response_preference` спасает `_clean_profile_text` (возвращает `None` при пустом), но `interests` через `_join_list` возвращает `""` → затирание.

**2.2. Keyword-гейт не пускает факты на извлечение** — `memory_engine.py:595-616`
- `should_extract_user_facts` требует слово из захардкоженного списка (`люблю/работаю/играю`...). Фразы «у меня кот по кличке Барон», «вчера сдал экзамен», «переезжаю на той неделе» → нет маркера → LLM-извлечение **не вызывается вообще**.
- Бонус: список `first_person_markers` содержит дубликаты («я » трижды) — список не вычитан.

**2.3. Рассогласование порогов importance** — `memory_engine.py:467` (показ ≥0.45) vs `:773` (запись ≥0.3)
- Факт записан в БД при importance 0.3–0.44, но в контекст не попадает. «Записал, но не использует».
- `_normalize_importance` поднимает известные типы до 0.65 (спасает большинство), но не все.

**2.4. Память per-(chat_id, user_id)** — `db.py:151`, hot-path в `agent.py:175`
- Факты не шарятся между чатами. В чате A знает человека, в чате B — чистый лист. (Профиль частично мёржится глобально, факты — нет.)

**2.5. Мало фактов в контексте** — `context_builder.py:132` (full=12), compact=4, minimal=2
- В обычном диалоге LLM видит ≤12 строк фактов (часто меньше при overflow). Полное досье (20) — только по триггер-фразам «что обо мне знаешь» (`context_builder.py:933`).

**2.6. Извлечение только из последнего сообщения** — `memory_engine.py:999`
- Факты, размазанные по нескольким репликам, не собираются.

### Что сделано ХОРОШО (не трогать)
- Анти-загрязнение: чужие сообщения помечены «Другой участник чата» (`memory_engine.py:1031`).
- Идентификация по стабильному `user_id` — люди между собой не путаются.
- `get_user_profile_merged` корректно приоритезирует приватный профиль.

### План правок — память
- [ ] **2.1** Фикс затирания: в `maybe_store_user_profile` НЕ передавать пустые значения в upsert (передавать `None`), либо в `db.upsert_user_profile` трактовать `""` как «не менять». Решить на уровне upsert — безопаснее (защитит все вызовы). Добавить тест.
- [ ] **2.2** Ослабить `should_extract_user_facts`: расширить список маркеров / снизить строгость, либо извлекать чаще (по длине/наличию существительных). Не ломать защиту от мусора (roleplay/спам).
- [ ] **2.3** Синхронизировать пороги: либо опустить `FACT_CONTEXT_MIN_IMPORTANCE` до 0.3, либо поднять порог записи. Выбрать одно значение правды.
- [ ] **2.5** Увеличить `memory_lines` для full-плана (12→~16-20) и/или чаще показывать досье. Проверить бюджет токенов.
- [ ] **2.4** (опционально, крупнее) Кросс-чатовое слияние фактов — отдельной задачей, оценить риск загрязнения.

## 3. БАГИ / СТАБИЛЬНОСТЬ (приоритет: критичный, риск: высокий — async/DB)

### CRITICAL
**3.1. Общее aiosqlite-соединение + interleaved transactions** ⚠️
`db.py:196-206` (`_transaction`), `agent.py:378-407` (background tasks)
- Одно `self.conn` на весь процесс. Большинство записей autocommit, но `replace_context_file`/`delete_context_file` открывают явный `BEGIN`. Фоновые задачи прошлого хода делают `commit()` поверх → преждевременный commit чужой транзакции или `OperationalError: cannot start a transaction within a transaction`.
- Самая вероятная причина «коряво/теряет данные».

**3.2. Мьют новичков не работает** — `main.py:578-594`
- `can_send_messages=True` разрешает текст. Telegram-мьют ничего не делает для текста; блокирует только in-memory гейт, который теряется при рестарте. Должно быть `can_send_messages=False`.

### MAJOR
**3.3. `/sleep` рубит соединение под незавершёнными задачами** — `main.py:739-741`, `1433-1439`
- `db.close()` + `bot.session.close()` сразу, in-flight `on_message` и `_background_tasks` не дожидаются → исключения + потеря записей последних ходов.

**3.4. Ложные пинги: `[hello]` → `@hello`** — `sanitization.py:51,180-185`, применяется к исходящим `main.py:1224`
- `BRACKET_USERNAME_RE` превращает любой `[слово]` 5–32 симв. в `@mention` → пинг случайных/несуществующих юзеров.

**3.5. `_deterministic_now_answer` затирает любой ответ** — `agent.py:251-253`, `generation_pipeline.py:469`
- Фраза «щас/сегодня» + вопрос → весь ответ безусловно заменяется шаблоном про время. «что щас по плану на сегодня» → сухой ответ про дату.

**3.6. Reaction-ack путь без per-chat lock** — `main.py:1325-1417`
- `on_message_reaction` пишет в БД без `get_chat_turn_lock` → гонки с `on_message` на общем соединении (усугубляет 3.1).

**3.7. `_keep_typing` сломанная логика shield** — `main.py:1169-1184`
- `wait_for(shield(sleep(4)), 4.1)` бессмысленно; детачит sleep, может крутить send_chat_action после стопа. `_typing_task` отменяется, но не дожидается.

**3.8. Потеря ответа при web-фейле** — `generation_pipeline.py:699-701`
- Пустой web_result → `answer=""` → `continue` на следующий (урезанный) context plan, выбрасывая уже сгенерированный основной ответ.

### MINOR (по возможности)
- **3.9** `_extract_code_candidate` — любой 4-значный набор проходит верификацию (`moderation.py:87`).
- **3.10** Эмодзи-реплай путь пропускает mood/identity/extraction задачи (`main.py:1092-1119`).
- **3.11** История пишет `stripped_text`, а агент отвечает на `agent_input_text` — рассинхрон для voice/reply (`main.py:1026-1064`).
- **3.12** Wakeup/sleep broadcast шлёт во ВСЕ активные чаты (`main.py:240-246`).

### План правок — баги
- [ ] **3.1** Сериализовать запись в БД: общий write-lock ИЛИ отдельное соединение для фоновых задач ИЛИ убрать явные `BEGIN` в пользу autocommit. Выбрать минимально-инвазивный вариант. **Самый важный фикс.**
- [ ] **3.2** `main.py:578`: `can_send_messages=False` при мьюте новичка.
- [ ] **3.3** `/sleep`/shutdown: дождаться in-flight задач и `_background_tasks` (с таймаутом) перед `db.close()`.
- [ ] **3.4** `sanitization.py`: ужесточить `BRACKET_USERNAME_RE` (только реальные `@username` или известные ники), не пинговать произвольные `[слово]`.
- [ ] **3.5** `agent.py`/`generation_pipeline.py`: `_deterministic_now_answer` — не затирать ответ безусловно; срабатывать только на явный прямой вопрос «который час/какое сегодня число», а не на любую «щас/сегодня».
- [ ] **3.6** `main.py`: reaction-ack под `get_chat_turn_lock`.
- [ ] **3.7** `main.py`: упростить `_keep_typing` (обычный cancel + await, без shield-обёртки).
- [ ] **3.8** `generation_pipeline.py`: при web-фейле не выбрасывать основной ответ.
- [ ] **3.9-3.12** — по остаточному принципу, после критичных.
